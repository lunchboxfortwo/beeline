# Body agent invariants

- **A closed connection is the only reconnect trigger.** `live-link.ts` owns the machine socket and uses OS TCP keepalive; it has only connected/disconnected states. Free-agent VMGenID resume events terminate the restored attempt through that same owner; its actual close opens the successor (`free-agent-resume.ts`, `machine-link-recovery.test.ts`). Failed upgrades preserve connection demand and finish on response `close`, including truncated bodies; only a complete explicit update-required response hands off to the updater. Discovery failures, refused requests, turn deadlines, successful initial snapshots and local progress never replace it. After intake failure, `room-supervisor.ts` requests a close through that owner and waits for the next authenticated open before reading again. A failed pushed command snapshot follows the same close and reconnect path in `daemon-api-client.ts`. Coverage: `room-supervisor.test.ts`, `intake-reconnect.test.ts`, `helper-operation-socket.test.ts`, `machine-link-recovery.test.ts`, `live-link-handshake.test.ts`, `machine-link-rollout.test.ts`.

- **Helper claims bind the authenticated machine connection.** Every claim carries its connection ID and epoch. `connection-presence.ts` returns that connection's claimed commands to pending on close and recovers pre-upgrade ownerless helper claims at registration, preserving MCP claims; it never manufactures a terminal turn from silence. `HelperTurnChannel` retains only generation ownership bookkeeping. Requests keep their IDs through socket loss and read their original results on reconnect; effects are not blindly replayed. Coverage: `helper-turn-channel.test.ts`, `agent-command.integration.test.ts`, `machine-connection-drop.test.ts`.
- **One invocation handles the current place.** `server-command-intake.ts` uses `claimAgentTurn` for one atomic claim of pending inputs at its Room. It prompts from the latest wake and current conversation, brief and live state, including every private order/report once with its request ID, files and return route, and every claimed schedule run's prompt once, since schedule prompts are not in the conversation. Missed mentions and lifecycle notifications are not individual jobs to replay. Tools select their private delivery with `requestId`; corner reports follow the latest human-approved revised brief author at its dispatch place, falling back to the opening route. Earlier explicit orders retain their issuer. `releaseAgentTurn` consumes remaining claimed wakes when the invocation ends. New arrivals remain pending for a follow-up; connection loss retains unfinished delivery through the connection owner. Hosted model access remains scoped to the Room/agent/generation/connection while any command is claimed. Diagnostics retain traces and usage. Coverage: `agent-return-queue.postgres.test.ts`, `agent-turn-batch.test.ts`, `command-result-context.test.ts`, `owned-model-invocation.test.ts`.

- **The helper is a monolith-only thin Room client:** `ThinDaemonCore` → `RoomRuntimeCoordinator` → `MonolithRoomTurnLoop`, every operation through `DaemonApiClient`. Room and corner loops share `agent-home.ts`, `acp.ts`, `agent-process.ts`, model selection, persona delivery, bwrap spawning, and the agent MCP (`read-only-mcp.ts`).
- **Agent processes have one owner and no capacity ceiling.** `agent-process.ts` starts a harness on work, serializes turns within a conversation, and stops it after one configurable stay-warm countdown from its last completed work. New work cancels that countdown; there is no sweep, suspend/resume, LRU or slot wait. `AgentTurnDeadline.run` bounds each admitted invocation to six hours, stops its harness and lets intake record failure and release the message; ACP itself has no request or silence timer. Process loss sends a `process-exited` interruption receipt; the server ends the claimed generation with one failure. New work starts a new turn. `/restart` retires harnesses while subscriptions keep serving. The setup wizard's RAM/CPU estimate warns without blocking. Architecture's `helper.agent-process` rule owns ACP start/stop calls; coverage: `agent-process.test.ts`, `acp-process.test.ts`, `server-command-intake.process.test.ts`, and the planted caller in `scripts/architecture-invariants.test.mjs`.
- **Separate harness completion from reply publication.** `[harness-terminal]` logs native Claude assistant `end_turn`, native `result`, and the correlated ACP response without message content. A Claude subprocess remaining alive is normal. The correlated ACP prompt result ends its invocation even when tool-status metadata remains unfinished; never drain those statuses before releasing intake (`acp-process.test.ts`, `corner-ended-harness.integration.test.ts`). `claude-turn-completion.test.ts` covers schedule creation and queued wakes; its opt-in installed-adapter proof uses `BEELINE_TEST_CLAUDE_ACP` with a fake native CLI and no account/model. Final replies include tool steps and can exceed 64 KB: machine request identity hashing must accept the full daemon input, and socket request failures must return a correlated error so publication cannot leave a finished turn waiting (`machine-request-results.ts`, `daemon-live.test.ts`).
- **Daemon operation dispatch has one owner.** Every runtime operation uses `AgentChannel.requestOperation`; callers cannot acquire transport capabilities (`scripts/router-boundaries.mjs`, mutation tests in `router-boundaries.test.mjs`). The private HTTP adapter serves explicit one-shot repository credential readers only. Server HTTP ingress remains for installed older helpers and sandboxed tools, sharing `DaemonService` authorization. Operations run independently of the serial intake queue so external work cannot block Stop/subscriptions. Coverage: `helper-operation-socket.test.ts`, `daemon-live.test.ts`.

- **One machine handshake, all agents and capabilities.** `machine-helper.ts` hosts agents in-process; `machine-link.ts` registers them together and each Room reads its messages/commands and setup once on authenticated reconnect, then receives pushes. The native manager restarts an exited helper; there is no systemd watchdog or application heartbeat/pong timer. Server machine output and login/version changes belong to `machine-connection.ts`; request failure and backpressure cannot close it. `scripts/check-architecture.mjs` runs the AST connection boundary and its shrinking sink inventory. Helper timers are banned except the six-hour invocation deadline in `AgentTurnDeadline.run`, the stay-warm countdown in `AgentProcesses.workChanged` and the single cancellable update handoff timeout in `ReleaseTransaction.begin`. Local waits follow actual filesystem/process/connector events. Free-agent idle sleep is server-owned; browser shares renew only on viewer activity. Proofs: `scripts/machine-connection-boundaries.test.mjs` plants forbidden reconnect/timer paths; `machine-connection-drop.test.ts` drops the socket repeatedly across 24 Room turn flows.

- **Emulators belong to the host.** Agents request host access with `request_grant(kind:host, target:"127.0.0.1:5037", reason, purpose)`; only the host owner's signed Allow authorizes use of an already running emulator. Calling the tool again reads live grant authority and the host adb device list, confirms each transport, returns its address and serial, or tells the agent to report unavailable/refused without using an emulator. SDK platform-tools discovery in `buildAgentEnv` happens before the private HOME overlay; this exposes the client without authorizing emulator use. A host approval needs no sandbox remount and the next `request_grant` reads current authority in the same session. The helper never creates, boots, manages or stops emulators, starts adb servers, repairs KVM access, or provisions AVDs. `machine-control.ts` owns the read-only host probe; `read-only-mcp.ts` owns the grant tool. Regression: `host-emulator.test.ts`; CI guard: `scripts/check-no-emulator-start.mjs`.

- **Installed agent programs are authoritative.** Connect lists all supported harnesses and checks the selected program before probing. Runtime startup preserves missing-program install hints in Room receipts. Claude/Codex/Pi adapters receive the user program paths; adapter updates follow npm latest with a 24-hour publish-age delay, side-by-side installs and the shared session-start check before atomic adoption; optional bundled harness binaries remain omitted. The daily feedback-triage adapter check uses no login or credential. Commands, overrides and proof: [installed agent programs](agent-programs.md).

Handoff tools deliver reports, posts and orders that name private paths, with an advisory warning to the sender that recipients may not be able to open them. Upload deliverable files with `post_artifact` and cite their attachment filenames; required brief files still travel through the target brief. Tracked relative source citations remain valid.

### Android device proof from a corner

Use this route in the current corner; no session restart or `adb connect` is needed:

1. Call `request_grant(action:"request", kind:"host", target:"127.0.0.1:5037", reason:"Android device proof", purpose:"Check the Android change on an existing host emulator")`.
2. If permission is pending, end the turn and wait for the host owner's Allow. On the approval wake, repeat that call. Refused permission requires the host owner's decision before retrying.
3. The tool enumerates the existing host server, then confirms each listed emulator with `host-serial:<serial>:get-state`. Run one returned `adb -H 127.0.0.1 -P 5037 -s <serial> get-state` command; expect `device`. Keep the same host, port and serial options on every proof command, including `shell`, `install` and `exec-out`.
4. If a serial disappears between discovery and use, repeat the grant call for a fresh address. Never keep using a serial copied from an earlier turn. If none is available, ask the host owner to make a running emulator available, then retry the grant call. The agent never starts an emulator or adb server.

An Allow authorizes access; it does not reserve a device or keep it alive. The grant result is a current connection check, not a lease. Missing `adb` is a host SDK setup problem: ask the host owner to install platform-tools or repair the helper PATH, then retry the same route.

## Lifecycle, commands and model selection

Paths and commands below are relative to the repository root. Read these invariants before editing this area; named code and tests hold implementation detail.

### ACP startup

- **Slots own their own startup work.** `machine-helper.ts` dispatches each slot independently, including configuration reads, supervision and diagnostics; initialization failures become that slot's `needs-config`. Control replies publish the live snapshot without waiting for disk writes. `machine-helper.startup.test.ts` holds one configuration read while a sibling and native readiness proceed. Update preparation and handoff each have a three-minute cancellable deadline (`managed-update.startup.test.ts`); waiting for idle has no deadline and preserves the staged boot selection. An operation timeout abandons the attempt, records `lastError`, fences late completion and keeps the current release serving. No automatic retry or watchdog is added.

- **Failed activation owns its harness cleanup.** Room and corner loops stop an unusable prior client before replacement, and discard the new client if cold activation fails, including after session creation. Native resume failure still falls back on the same client. The explicit ACP `-32000 Authentication required` refusal produces a terminal `not-signed-in` receipt; provider refresh races retain bounded hiccup retries. Regression and real subprocess proof: `monolith-activation-failure.test.ts`.

- **ACP scopes bind to the helper's lifetime without ordering after its readiness.** `AcpResourceScope` (`apps/body/src/acp-resource-scope.ts`) keeps `BindsTo` without `After`: the notify helper can initialize ACP before READY, so ordering its scope after readiness can deadlock startup (`acp-resource-scope.startup.test.ts`).
- **Intake precedes retention work.** `room-runtime.ts` starts Room command loops and corner subscriptions without awaiting pending legacy migration; archived cleanup runs in the background and preserves unpublished work. Repository repair runs on the first fetch of an active cache, without scanning archived object stores at startup (`room-runtime.startup.test.ts`, `workloop-watchdog.test.ts`, `repository-cache-repair.test.ts`).
- **Native conversation memory survives helper restarts.** Codex/Grok Room and corner loops load the matching harness session and its delivered row IDs from private `agent-home/warm-transcript.json`. Configuration/checkout changes, failed native loads and the unchanged 30-minute idle boundary start cold; unsupported harnesses retain bounded transcript replay. Open Room storage preserves the resume record; archive removes it with the private home (`monolith-native-resume.test.ts`, `warm-transcript.test.ts`, `storage-bloat.regression.test.ts`).
- **Fixed context blocks are session scoped on verified harnesses.** Codex and Claude adapters use guarded instruction/compaction support; Pi checks its compaction journal before assembly. Changed blocks, cache misses, native loads, failed delivery, compaction and adapter restart restore context. The workspace-core task-start action remains per-turn. Version guards, two-model replay and native shell cap proofs: [token budget proof](agent-token-budget-proof.md); original Codex measurements: [Codex prompt delivery](codex-prompt-delivery.md).

### Tagged control commands

- **An exact tagged lifecycle command is server control, never a model prompt.** `routeHumanMessage` treats a whole message `@agent restart|status|stop|retry|debug|help|login` (or `@agent /restart`, `/login`) as control. Status/help follow access policy; restart, stop, retry and debug are open to anyone in the Room (debug reports only this Room's turn); login is owner-only. Restarts coalesce per agent in `agent_commands` until `ConnectionPresence` sees a new lifecycle id.

### Model catalog

- **A model picker is a live account verdict; readiness never waits for a harness.** `apps/body/src/model-catalog.ts` offers models proved through the live setter. Room and corner activation validate the server selection in the actual session; the persisted selection is only a fallback. Catalog publication runs independently after intake starts. No startup model request or diagnostic write may gate readiness (`agent-runtime.startup.test.ts`). Transient provider failures remain hiccups rather than model verdicts (`isTransientProviderText`, `isAuthShapedFault`).

- **Agent tool schemas stay compact.** `minimal-tool-surface.ts` declares the canonical ordinary tools; `read-only-mcp.ts` validates advertised schemas and maps only those tools to authorized internal operations; legacy tool names and unadvertised input aliases are refused. Procedure reads accept the advertised `slug` or `name`; message reads default to newest first, with explicit `from:oldest` retained. Squire approval resume wakes can use `no_reply_needed`. Workflow, wallet, browser-share and avatar schemas are discovered through `app_tool` first-party routes; no mid-session tool-list refresh is assumed. `room-session.ts` mounts repository/scratch fallbacks only when native IO is unproven, and deliberate silence uses the explicit `no_reply_needed` result. An offline Codex Room keeps scratch IO even with a native shell (`roomNativeIoProven` in `harness-capabilities.ts`). `revise_corner(action:brief)` accepts a complete brief projection copied from `read`; Body discards returned metadata and the server resolves approval and files again. Schedule updates/deletes still require a turn started by a human Workspace admin of the schedule’s Room; scheduled wakes are refused. Schedule prompts are bounded to 2,000 UTF-16 code units and report text to 16,000. Proof: `node --import tsx scripts/prove-tool-description-contract.mjs` after building Body and server (R1/R2). Measure exact descriptors with `npm run measure:agent-tools -- <output-dir>`; authority and privacy regressions live in `minimal-tool-surface.test.ts`, `commander.integration.test.ts` and `corner-lifecycle.test.ts`.

Run `node --import tsx scripts/prove-agent-tool-traps.mjs` after building Body and server for the isolated message-read, procedure-name, owed-tag, schedule-title, silent-feedback and Squire-silence proof (Reproduction 7).

Reviewer prompt targets use one live `getPrChecksStatus` read per wake, plus the current brief and local git head. A stored pending lifecycle cannot override live passing checks; a mismatched checkout or unavailable provider read gives an unverified-target instruction, never a claim that GitHub checks failed. Coverage: `monolith-corner-turn.test.ts`, Reproduction `stale-green`.

Run `npm run prove:reply-reconnect` for the isolated built-service reconnect race and model timeout proof.

## Turn ownership protocol rollout

`BEELINE_NETWORK_ROUTER_V1` defaults on for every deployment; explicit `0` retains the rollback setting shared by phone projections, helper activation, overlays, usage, turn ownership and MCP member delivery. Production composition is in `apps/server/src/network-router-runtime.ts` and `index.ts`. Each protocol still requires its matching negotiated capability. A selected claim binds its command and generation to the actual registered connection ID and epoch. Authenticated traffic renews the existing aggregate server lease; idle time never renews it. Lease writes never refresh `agent_turns.created_at`, command timestamps, or a user-state journal. Genuine start/progress/terminal transitions still persist. Actual connection replacement or release returns unfinished commands to pending. No per-turn expiry scan or retry timer is added.

The machine socket carries ordinary requests and source-bound claim, receipt and stop acknowledgement controls through the same request owner. A connection loss leaves pending requests waiting. The successor registration re-reads sent request IDs and subscribes to current Room commands. A changed authenticated owner stops its previous owned task once; a re-claimed command receives a fresh generation. A generation never rebinds to another source. Harnesses and MCP launch environments bind to their generation-specific command context path (`session-command-binding.test.ts`, `helper-turn-channel.test.ts`, `machine-link-recovery.test.ts`).

A terminal receipt confirms its exact completed command and immutable generation without acquiring work again. An unanswered command handed back to pending has no terminal result to confirm. Replies from a previously claimed generation may answer an unfinished job after reconnect; the first reply completes it atomically under the command row lock and retained current membership. Other effects from a new generation or foreign connection refuse the old effect (`turn-ownership-terminal-receipt.test.ts`).

Nullable source columns preserve old rows. All runtime active/expired command readers use the same effective-owner predicate, including counts, workflow recovery, command queues and tool authorization. The schema and owned-row meaning must remain on server rollback even if admission is disabled; an older server that ignores source ownership is below that protocol floor. This does not impose a new native binary minimum.

An actual owned database effect holds the existing authority writer fence and rechecks current Room/Workspace access inside its transaction before source and command locks; replies retain membership and command rows through publication without a connection fence. Other owned effects keep their source fence. Claim, stop acknowledgement and background completion use the same order. Each actual effect registers one ephemeral fence per transaction and source. Its deferred commit trigger checks the immutable generation, current registration and aggregate lease again at commit, then removes the evidence. An admitted transaction whose lease expires rolls back; authorization earlier in the transaction cannot extend the lease. Final socket replies check current source time immediately before synchronous enqueue. Unsupported owned external operations refuse before entering the provider until their own authority and durable UNKNOWN adapter is proven. Legacy effects retain their explicit compatibility path. The focused two-pool authority/effect proof is `turn-ownership-authority.postgres.test.ts`.

Failed corner receipts take the existing lifecycle lock before authority, matching close and account-removal writers; ordinary activity takes no lifecycle lock. Archival writers acquire authority before command, Room, member or fact row locks, including the human/helper close and merged-PR boundaries. Account deletion discovers its corner lock set without row locks and refuses a concurrent scope expansion before erasure; another explicit deletion attempt owns fresh discovery. All daemon operations return the first transaction failure without deadlock replay; another explicit action reacquires current authority (`turn-ownership-recovery.test.ts`, `R-BRIEF-DEADLOCK` in `commander.integration.test.ts`). No provider runs under these authority locks.

- **Initial Room data follows registration without a deadline.** Correlated inbox, command and subscribed frames complete initial data once; unrelated control frames cannot certify it. Only an actual connection close replaces the transport. Unsubscribe fences old awaited reads before a new subscription can complete. Coverage: `intake-reconnect.test.ts`, `machine-link-recovery.test.ts`, `machine-connection-drop.test.ts`.

Router admission is universal by default. Protocol negotiation, current grants, source ownership and listener readiness remain correctness requirements. Free-agent model access binds the request generation/current source (`owned-model-claim-socket.test.ts`); it must not borrow another owner's current command.
