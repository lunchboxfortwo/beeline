# Product behavior notes

Behavior notes that used to live in the README. Kept here so the README stays a front door.

Chats show up to three threads needing you beneath each chat; More expands the list to every thread, with yours waiting first. See the [state-mark grammar](DESIGN.md#typography) for chat and task symbols. The Tasks tab leads with Needs you, grouping requests and approvals by thread, each clearable, with Clear all. See the [server projection](agent-server-surfaces.md) for eligibility rules. In progress holds active threads, then idle ones; In review is part of it. Backlog holds parked threads and work not yet started; Done shows the last seven days. Tap a task's name to open its thread, or its status mark to open its objective and details. Tasks without a thread open details from either target. In details, Backlog parks a thread, In progress takes it out of Backlog, and Done closes it with the same permissions as Close. Archived threads stay Done and offer no state picker. Tasks can be assigned to an agent or a person. Replies quote the asking message in its original conversation. Filter by chat or assignee. Decision cards follow the [server projection](agent-server-surfaces.md); agent inputs follow the [messaging contract](agent-corners.md). Agents use `create_work_item` to add work with an objective (Backlog by default; the objective passes into the thread when the work starts), `set_work_state` and `assign_work_item` (agent, person or unassigned). These use the same work-item update path as `update_work`.

Messages to helper agents stay in their server queue until an answer is posted to the recorded chat.
After reconnecting, each chat’s backlog arrives in one turn with a private note saying how long the agent was offline and that the work may be outdated. Repeated runs of the same schedule collapse to the newest run; the agent answers each asker in its combined reply.
Messages that arrive while an agent works stay queued for its next turn. Waiting messages from the same chat receive one combined answer; a stopped turn cannot silently close a new human request. Automatic corner reminders can finish quietly when there is no update, and obsolete idle reminders are discarded. Idle reminder budgets and recipient-specific worker-block clearing follow [corner lifecycle invariants](agent-corners.md).
Repository setup and optional session resources run through session tools; their errors reach the agent so it can still answer.
Saved answers survive reconnects and helper updates without another agent turn.
An unavailable personal agent leaves its messages queued and shows “agent is offline · connect again”. Hosted starter agents receive their model credential with each queued request; if their harness cannot start, the turn fails visibly with its actual reason.

Reply quotes preview at most two lines on phone and web/desktop; the reply’s own message text wraps in full. Viewer provenance stays on one line.
