# System lines and event invariants

Paths and commands below are relative to the repository root. Read these invariants before editing this area; named code and tests hold implementation detail.

## System lines and events

- **System wording lives in one catalog.** `packages/api-contract/src/system-message-catalog.ts` holds exact text fragments and ordered variable slots. Writers call `systemMessage(key, ...data)`; dynamic names, user-authored text and provider data remain inputs. Retired status templates and their senders are deleted; only conversation history, explicit requests and the external-agent offline notice belong in chat. New, removed and changed phrases are reviewed weekly after merging; there is no wording approval lock or blocking gate. `apps/server/system-message-wording.lock.json` is a regenerated review snapshot only; tests validate catalog shape and source use without comparing its hashes. `system-message-catalog.test.ts` guards against reintroducing retired wording; producer regressions cover silent status paths and preserved workflow, membership and transaction history. Run `NODE_OPTIONS=--max-old-space-size=4096 npm test -w @beeline/server -- --run src/system-message-catalog.test.ts --maxWorkers=2 --minWorkers=1`. The former function/dependency fingerprint lock has been removed.

- **An agent's name carries only its model's words.** `apps/server/src/message-origin.ts` types every message and queue write by who composed it (model, product-onboarding, system, person); agent-authored writes accept only model or product-onboarding text, so server-composed prose under an agent's name fails to type-check. Product-onboarding is the hello, starter welcome, Luna intro, game caption, join greeting and invite link. Machine reports and lifecycle payloads are System text under the System author. GitHub prints failures only: a green rollup advances the corner and the reviewer's wake cites its `requested review of` line. An agent that cannot answer until its owner acts gets one System entry: a sign-in is one `agent-sign-in` card (`<agent> needs to sign in`) that settles in place; a spent allowance is one `<agent> is out of its limit · resets at <time>` line (`agent-needs-owner.ts`, from the helper's failed receipt `reasonKind`).
- **Disclosure rows have no top edge.** Steps and grouped GitHub events retain a 44 px minimum tap height. `LedgerDisclosure` owns all expandable system rows, including steps, event runs, tool output and scripts. `TranscriptNavigationRow` owns their child rows. Hairlines appear only between sibling child rows; first children and standalone records have no upper boundary.

- **One producer, one grammar.** `apps/server/src/system-line.ts` produces every `system`/`card` line as `<subject> <verb>[ <object>][ · <consequence>]` (past tense, `@handle` names, no colon/em dash/trailing period; `system-line.contract.test.ts`). The phone renders each system message separately with `LedgerSystemLine` (`buzz/system-lines.ts`), using two-line previews and a muted right/down chevron only for measured overflow (`Ledger.test.ts`, `system-lines.browser.test.ts`); agent tool runs fold together. Consecutive repository notifications and passive wallet records fold into collapsed event runs (`buzz/pr-lifecycle.ts`, `PrLifecycleCard.tsx`): repository-only groups use their own header; other groups use `LedgerDisclosure`. Expansion retains one line per committed event. Corner Opened facts anchor `CornerOpenedMarkers` beneath the requesting message in its Room, DM or corner and never change on merge or close. Without a real dispatching message in the command Room, no opening line is posted. Off-call-site parent Rooms receive no opening record. Corner-linked PR event rows stay in the parent Room unless another room holds an anchored opening; a source-free opening does not move them, and corner watch wakes stay private commands in the watcher room. Legacy stored duplicates are hidden by the shared read visibility rule. Corner open rows lead with `CornerGlyph`; GitHub rows have no leading glyph. Merge and close are represented only by deduplicated PR events in the parent Room when no other room holds an anchored opening; PR rows open the corner. Private orders/reports have no transcript marker; automatic wakes never borrow a historical root message. Cleanup stays silent. Human/agent messages and actionable cards end the run; check history retains its posted state while the corner header owns live state. Coverage: `corner-callsite.integration.test.ts`, `CornerOpenedMarker.test.tsx`, `pr-accordion.test.ts`, `ci-accordion.test.ts` and their browser regressions.
- **A line's `kind` is the contract; its `verb` is prose.** `packages/api-contract/src/system-events.ts` owns `SERVER_EVENT_KINDS`/`RESUME_KINDS`/`CONTROL_KINDS`/`MAX_*`, plus one `SERVER_EVENT_KIND_DETAIL` line per kind (`eventKindCatalogLines`) — the single source `subscribe_events` and the agent rulebook both read, so a kind with no detail fails to compile rather than drift silently. `systemLine()` resolves explicit targets and prompt-free subscribers from the subscription owner, and `routeSystemCommand` turns a kinded line into input/resume/stop with no sender access check. A `PER_ITEM_EVENT_KINDS` kind wakes its owner, never subscribable; `SUBSCRIBABLE_EVENT_KINDS` is. After changing event kinds, run `npm run codecs:generate`; `npm run codecs:check` verifies the derived wire/helper codecs.
- **Subscriptions are event-driven actions without approval.** `apps/server/src/agent-subscriptions.ts` stores a Room or covered repository event plus its prompt/optional workflow target; `agent_subscriptions` is the only actionable store. `subscribe_events` replaces the same Room/event keys as prompted actions: a retained key keeps its explicit prompt, and deleting through either API stops that action. Prompt-free subscriptions preserve direct-event wakes; prompted subscriptions emit one `subscription-fired` line per event/key. `room_event_subscriptions` projects the parent inheritance requested through `subscribe_events` into corners (preserved independently of a prompt on that key by `inherit_to_corners`); `corner_person_state.subscriptions_overridden` preserves an explicit empty corner preference without storing another action list. Leave/removal producers declare `left` and dispatch immediately; the upgrade import retains the old free-agent sweep’s recent unkinded-fact window once through normal command routing. Old membership/corner JSON is upgrade input only (`migrateMembershipSubscriptions`), and old phone subscription IDs decode to this same owner. Verified GitHub App deliveries emit one per matching repository subscription per delivery. `subscriptionActionPrompt` (`packages/api-contract/src/subscriptions.ts`) puts the trusted action before the quoted untrusted payload. The phone's Schedules and subscriptions page lists these with the same detail grammar and stop control. Connected Slack channel messages register a Composio webhook trigger on the existing account (`composio-apps.ts`); `/v1/connectors/events/composio` verifies the signed delivery and dedupes each subscriber wake. Linear and Stripe provider hooks run through the helper's official MCP credential and `provider-webhooks.ts` on both sides; the server verifies signatures and dedupes each subscriber wake. `list_subscription_events` advertises connected sources with a delivery path; Gmail and Squire-only connections are not offered yet.
- **An agent subscribes and emits for itself; the server owns the cause.** `subscribe_events` edits the caller's single-store Room subscriptions; `emit_event` acts only in its Room. `systemLine` derives cause/root/depth from the committed cause without a lock or cascade depth/turn budget. Unavailable causes still refuse the write. Caused lines sort at `GREATEST(now(), cause+1s)`.
- Approval cards resume paused turns through `RESUME_KINDS`, never typed human confirmation. Squire approved/denied pushes arrive on the originating `SquireTaskRelay` connection, retained past the asking turn, including vault operations without a browser session. A completed ask receives one new input turn with the decision and original provenance; a live ask retains its output authority and resumes as before. The relay handles a decision sharing the pending result's stdio read after registering that result. Never poll or synthesize expiry: Squire sends no expiry event. Coverage: `squire-task-relay.test.ts`, `squire-mcp-client.test.ts`, `squire-approval-wake.test.ts`, `integration/connectors-2.test.ts`.

## Retired status storage

After serving and rollback versions drain, drop `agent_schedules.last_reported_blocking_run_id`
and `connection_receipts.message_id`/`event_class`: skipped-run and usage-receipt chat notices
have no runtime producer or consumer. The usage ledger retains its operation, result and bytes.
Removing the receipt aggregate also exposed `institutional_context_serves.total_bytes` as unread;
that derived metric is registered for the same post-drain cleanup. Keep these schema columns
until that separate migration; do not add a notice or a reader to preserve dead storage.
